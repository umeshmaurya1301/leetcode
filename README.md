> Everything below the *Layout* section is generated by [`tools/gen_readme.py`](tools/gen_readme.py) — don't hand-edit the tables.

## Layout

Every `.java` file under `src/` sits in a lowercase package named after its topic, is self-contained (own `package`, own `import java.util.*;`, one top-level class named after the file), and carries a `main` that runs the problem's worked examples against `// expected:` comments.

**A solution is filed under every technique it uses.** A problem solved with a sliding window over a hash map lives in *both* `slidingwindow/` and `hashing/` as byte-identical copies — different package, different fully-qualified name, so both compile side by side. Browsing one topic folder therefore shows every solution that technique applies to.

The trade-off is real: **editing a solution means editing all of its copies.** Each topic table has an *Also in* column pointing at the siblings, [the last table](#files-with-copies-in-more-than-one-package) lists every multi-homed file, and `python tools/gen_readme.py --check` fails loudly if two copies ever drift apart.

Problems with more than one documented approach (e.g. brute force vs. optimal) get one file per approach, suffixed `_1_…`, `_2_…`, and each approach file is filed by *its own* technique — so LIS lands its two DP files in `dynamicprogramming/` and its patience-sorting file in `binarysearch/`.

## Build & run

No build tool. Compile everything at once, then run any solution by its fully-qualified name:

```bash
# compile all packages
javac -d out $(find src -name "*.java")

# run one solution's worked examples
java -cp out slidingwindow.LT_0076_Minimum_Window_Substring
java -cp out dynamicprogramming.LT_0322_Coin_Change

# verify no duplicate copies have drifted, and refresh this README
python tools/gen_readme.py
```

On PowerShell:

```powershell
javac -d out (Get-ChildItem -Recurse -Filter *.java src | ForEach-Object FullName)
java -cp out slidingwindow.LT_0076_Minimum_Window_Substring
```
